# MCPize packaging (B2 of issue #33)

Part 2 of the recall check MCP server: the deployment facts, the pricing
and payout steps, and the listing copy for the merged core (`mcp_server/`,
issue #37, PR #41) on MCPize, described in the task that created this work
as follows.

Source: [issue #33, B: Recall check MCP server for MCPize](https://github.com/nnyycc77-ship-it/tiny-ledger/issues/33)
> MCPize (mcpize.com) hosts MCP servers itself and settles per call payments in USDC on Base to the seller wallet at an 80 percent creator share, which removes the hosting blocker that parked the pay per call API.

## Status

MCPize's GitHub app generated the deployment configuration itself: pull
request #45 added [`mcpize.yaml`](../../mcpize.yaml) at the repository root,
the owner merged it on 2026-10-23, and the app's pull request text states
the server is live under the id `recallcheck`. That action was the owner's,
outside this repo; this folder records it with the source quoted in
[`DEPLOYMENT.md`](DEPLOYMENT.md) and does not itself connect to or verify
the live endpoint. Pricing, payout and the listing copy are still to be
set in the MCPize dashboard by the owner; nothing in this repo sets them,
and no price, network or wallet is written here.

## Verification

```sh
python3 -m unittest discover -s tools/tests -p 'test_mcpize_listing.py' -v
```

The test re-renders the recorded CPSC capture through the real server
(offline, fetcher patched) and checks the example in `LISTING.md` equals
that output byte for byte, that the tool name and every argument named in
the listing match the server's live `tools/list` schema, that the track
record paragraph quoted in the listing matches `AGENT-BRIEF.md` byte for
byte, that the root `mcpize.yaml` starts the core's entry point and carries
no pricing or wallet field and is quoted in the notes exactly, and that no
sentence of this folder's own (quoted sources aside) claims a deployment or
listing was done by this repo.
